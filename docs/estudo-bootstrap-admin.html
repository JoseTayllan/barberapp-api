1. Objetivo do bootstrap

O bootstrap cria o primeiro administrador da aplicação de forma controlada. Ele não é endpoint e não deve permanecer habilitado para administrar usuários no dia a dia.

Ideia central: habilitar temporariamente, criar o administrador inicial, confirmar a role Admin e então desabilitar o bootstrap e remover os valores sensíveis do ambiente.

As roles Admin, Barbeiro e Cliente continuam sendo verificadas mesmo quando a criação do administrador está desabilitada.

2. Compilação × inicialização

Compilar e executar são etapas diferentes:

Compilar o código ↓ Executar o Program.cs ↓ Ler as configurações ↓ Validar e consultar o banco ↓ Aceitar requisições HTTP

Na compilação, o C# verifica tipos e produz o programa. As variáveis de ambiente são lidas e o usuário é procurado no banco somente quando a aplicação está sendo executada e inicializada.

Atenção: os aproximadamente 900 ms não são tempo de compilação. Essa espera só pode ocorrer quando duas instâncias disputam a criação do mesmo administrador.

3. Variáveis de ambiente

O .NET reúne várias fontes em builder.Configuration. Nas variáveis de ambiente, dois sublinhados representam os dois-pontos usados na chave interna:

Variável de ambiente Chave no .NET
BootstrapAdmin__Enabled BootstrapAdmin:Enabled
BootstrapAdmin__NomeCompleto BootstrapAdmin:NomeCompleto
BootstrapAdmin__Email BootstrapAdmin:Email
BootstrapAdmin__Password BootstrapAdmin:Password 
var bootstrapAdminEmail = bootstrapAdminEnabled
    ? GetRequiredConfiguration(
        builder.Configuration,
        "BootstrapAdmin:Email")
    : null;

O operador ternário pode ser lido assim: “se o bootstrap estiver habilitado, leia e valide o email; caso contrário, use null”.

4. Validação e fail-fast

static bool GetBootstrapAdminEnabled(IConfiguration configuration)
{
    const string key = "BootstrapAdmin:Enabled";
    var value = configuration[key];

    if (value is null)
    {
        return false;
    }

    if (string.IsNullOrWhiteSpace(value) ||
        !bool.TryParse(value, out var enabled))
    {
        throw new InvalidOperationException(
            $"A configuração '{key}' deve ser um booleano válido.");
    }

    return enabled;
}
Valor Comportamento no startup
Variável ausenteRetorna false; bootstrap desabilitado.
"false"Conversão válida; bootstrap desabilitado.
"true"Conversão válida; bootstrap habilitado.
Vazio ou espaçosConfiguração inválida; aplicação não inicia.
"sim" ou "1"Conversão inválida; aplicação não inicia.

Os dois resultados de TryParse

var conseguiuConverter =
    bool.TryParse("sim", out var enabled);

// conseguiuConverter == false
// enabled == false

conseguiuConverter informa se o texto era um booleano válido. Já enabled contém o valor convertido. Como "sim" não é válido, o código lança uma exceção em vez de desabilitar silenciosamente.

Fail-fast: configuração errada deve ser detectada imediatamente. Isso evita que a aplicação pareça saudável enquanto executa com uma intenção diferente da configurada.

5. Escopo, RoleManager e UserManager

using (var scope = app.Services.CreateScope())
{
    var roleManager = scope.ServiceProvider
        .GetRequiredService<RoleManager<IdentityRole>>();

    var userManager = scope.ServiceProvider
        .GetRequiredService<UserManager<ApplicationUser>>();
}
  • CreateScope() cria um escopo temporário de dependências durante a inicialização.
  • RoleManager verifica e cria roles.
  • UserManager procura, cria, remove usuários e administra suas roles.
  • GetRequiredService exige que a dependência esteja registrada; se não estiver, a inicialização falha.
  • O using libera o escopo e seus recursos ao terminar.

Esse escopo é manual porque ainda não existe uma requisição HTTP. Em uma requisição normal, o ASP.NET Core criaria e encerraria o escopo automaticamente.

6. Fluxo completo

  1. A aplicação lê BootstrapAdmin:Enabled.
  2. Se estiver habilitado, exige nome, email e senha.
  3. Cria um escopo temporário.
  4. Verifica as roles Admin, Barbeiro e Cliente.
  5. Procura o email configurado com FindByEmailAsync.
  6. Se o usuário não existir, cria com CreateAsync.
  7. Associa a role Admin com AddToRoleAsync.
  8. Se a role falhar, tenta remover o usuário recém-criado como compensação.
  9. Se outra instância estiver criando o mesmo admin, espera limitadamente pelo resultado dela sem promover a conta.
  10. Somente depois desse startup a API começa a atender normalmente.

7. Decisões de segurança

  • Não existe email ou senha administrativa fixa no código.
  • A senha não aparece nas mensagens dos testes nem nos logs.
  • Erros do Identity expõem somente códigos, não descrições potencialmente sensíveis.
  • Uma conta existente sem a role Admin nunca é promovida automaticamente.
  • O bootstrap deve ser desabilitado após a criação inicial.
  • Falha de compensação pode deixar estado parcial e exige inspeção manual.
Nunca faça: colocar uma senha real neste documento, em arquivos versionados, comandos compartilhados, screenshots ou logs.

8. Exercícios

Tente responder antes de abrir cada solução.

Exercício 1

O que acontece quando BootstrapAdmin__Enabled não existe?

Mostrar resposta

O método retorna false. O bootstrap do usuário fica desabilitado, mas a aplicação continua e ainda garante as roles.

Exercício 2

Por que "sim" não deve ser tratado silenciosamente como false?

Mostrar resposta

Porque pode ser um erro de quem pretendia habilitar o bootstrap. Falhar imediatamente revela a configuração incorreta e evita uma inicialização enganosa.

Exercício 3

Qual componente procura o usuário no banco?

Mostrar resposta

O UserManager<ApplicationUser>, usando métodos como FindByEmailAsync.

Exercício 4

Por que o bootstrap cria um escopo manual?

Mostrar resposta

Porque o startup acontece fora de uma requisição HTTP. O escopo permite usar corretamente dependências de vida curta, como os managers e o contexto do banco, e liberá-las ao final.

Exercício 5

Em qual momento o usuário é procurado: compilação, inicialização ou atendimento de uma requisição?

Mostrar resposta

Durante a inicialização, depois da compilação e antes de a API começar a atender requisições.

  • Diferença entre compilar e executar.
  • Conversão de __ para :.
  • Diferença entre o retorno de TryParse e o valor em out.
  • Significado de fail-fast.
  • Responsabilidades de RoleManager e UserManager.
  • Motivo do using no escopo.
